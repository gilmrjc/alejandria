# Paso 3: Documentación de Resultados

## Formato de Respuestas Validadas

Para cada gap resuelto, documenta la respuesta en el documento original usando este formato:

```text
**[CATEGORÍA TEMÁTICA]**

**GAP RESUELTO: [Título del gap]** [PRIORIDAD]
- **Pregunta original**: [Pregunta específica]
- **Respuesta**: [Respuesta validada por el usuario - debe ser auto-contenida y expandida]
- **Razonamiento**: [Justificación establecida en sesión]
- **Rol afectado**: [Roles funcionales afectados]
- **Referencias**: [Fuentes consultadas si aplica]
```

## Actualización del Documento

### Incorporación al contenido principal

- Si la respuesta es un concepto fundamental, agrégalo a la sección apropiada del documento
- Si es una definición, agrégala a un glosario o sección de definiciones
- Si es un razonamiento, agrégalo como contexto de la decisión relacionada

### Mantenimiento de trazabilidad

- Mantener referencia al gap original en la sección de gaps resueltos
- Preservar el historial de iteraciones si fue complejo

### Limpieza de gaps resueltos

- Una vez que los gaps resueltos se hayan integrado al contenido principal del documento, eliminarlos de la lista de gaps
- Esto mantiene el archivo limpio y enfocado en los gaps pendientes
- La eliminación debe ocurrir después de confirmar que la información está correctamente incorporada en el documento

## Validación de Incorporación

Después de incorporar respuestas al documento:

- Solicitar al usuario que revise dónde se incorporó cada respuesta
- Verificar que las respuestas se incorporaron en el lugar correcto
- Detectar contradicciones nuevas introducidas por las respuestas
- Sugerir ejecutar el proceso de identificación de gaps después para validar mejoras

## Gaps Persistentes

Si un gap no puede resolverse en la sesión:

```text
**GAP PERSISTENTE: [Título del gap]** [PRIORIDAD]
- **Pregunta original**: [Pregunta específica]
- **Estado**: Pendiente de [acción requerida]
- **Sugerencia de investigación**: [Qué investigar o a quién consultar]
- **Stakeholders a consultar**: [Personas o roles a involucrar]
- **Responsable sugerido**: [Rol funcional]
- **Fecha límite sugerida**: [YYYY-MM-DD si aplica]
```

## Seguimiento de Gaps Persistentes

Para gaps que persisten entre sesiones:

- Crear sistema de seguimiento con responsables y fechas límite
- Programar sesiones de seguimiento automáticas para gaps persistentes
- Priorizar gaps persistentes en sesiones futuras
- Revisar planes de acción de sesiones anteriores
- Verificar si hay nueva información disponible

## Criterios de Terminación

### La sesión se considera completa cuando

- Todos los gaps priorizados para la sesión han sido abordados
- Las respuestas validadas han sido incorporadas al documento
- Los gaps persistentes han sido documentados con planes de acción
- La validación de incorporación se ha completado
- El usuario confirma que está satisfecho con el progreso

### Criterios de calidad

- Cada respuesta tiene razonamiento claro y validado
- Las respuestas son auto-contenidas y entendibles sin contexto adicional
- Las definiciones son precisas y aplicables al contexto
- Los razonamientos están bien fundamentados
- El documento refleja el estado actual del conocimiento del equipo
- Los gaps persistentes tienen caminos claros para resolución futura
- No hay contradicciones nuevas introducidas por las respuestas
