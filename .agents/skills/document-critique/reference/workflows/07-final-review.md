# Paso 7: Revisión Integrativa Final

Después de completar el bucle para todos los roles funcionales relevantes y la evaluación de calidad, realiza una revisión final para asegurar que todas las perspectivas estén reflejadas.

## 5.1 Verificar Cobertura Multi-Rol

- Confirma que cada rol funcional relevante ha sido revisado
- Valida que las necesidades de cada rol están documentadas
- Identifica roles que puedan haber sido omitidos

## 5.2 Verificar Perspectiva Dual Consistente

- Confirma que cada sección del documento tiene contexto para seniors (decisiones, razones fundamentales, impacto en el negocio/organización/largo plazo) adaptado al tipo de documento
- Confirma que cada sección del documento tiene contexto para juniors (pros/contras, conceptos del dominio, terminología, paso a paso) adaptado al tipo de documento
- Identifica gaps donde una perspectiva pueda estar faltante

## 5.3 Identificar Contradicciones Entre Roles

- Busca contradicciones en la información presentada desde diferentes perspectivas de rol
- Documenta discrepancias entre lo que dice un rol versus otro
- Sugiere resolución de conflictos

## 5.4 Validar Completitud Global

### Criterios de Calidad (idealmente cumplidos)

- Los gaps identificados están organizados temáticamente
- Los gaps de alta prioridad tienen referencias o sugerencias de investigación cuando aplica
- Las referencias son específicas (con URLs de GitHub, números de línea cuando aplica)

## 5.5 Sugerir Consolidación Temática

Proponga organizar los hallazgos temáticamente en un documento estructurado, asegurando que:

- Las decisiones técnicas se consoliden para desarrolladores y arquitectos
- El contexto de negocio se consolide para product managers
- Los procedimientos operativos se consoliden para operaciones y soporte
- La perspectiva dual (senior/junior) se mantenga en cada sección consolidada

### Recomendaciones de Acción

Prioriza editar el documento actual sobre crear nuevos documentos. Crea nuevos documentos solo cuando:

- Hay más de 10 gaps relacionados con un tema específico
- El contenido excede el 30% del tamaño del documento actual
- El contenido pertenece a un dominio funcional diferente (ej. gaps de arquitectura en un PRD, gaps de cultura en un documento técnico)

Consulta `references/priorities.md` para tipos de documentos recomendados y criterios de consolidación.
